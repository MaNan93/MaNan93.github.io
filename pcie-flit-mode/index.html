PCIe Flit Mode：能力、声明与协商

把 Flit Mode Supported、Flit Mode Disable、TS Advertisement、Flit_Mode_Enabled 和 Flit Mode Status 放回 LTSSM 时间线上理解。

2026-09-14 · PCIe · Flit Mode · LTSSM
核心结论：Flit Mode 是 Data Stream Mode，64 GT/s 是 Data Rate。两者不是一个概念。64 GT/s 要求 Flit Mode，但 Flit Mode 并不要求 64 GT/s。

1. 五个术语分别是什么

名称性质位置含义
Flit Mode SupportedCapabilityPCI Express Capabilities RegisterComponent 是否具备 Flit Mode 能力
Flit Mode DisableControlLink Control Register是否禁止使用 Flit Mode
Flit Mode Supported bitAdvertisementTS1/TS2 Data Rate Identifier在线路上向 Link Partner 声明本次训练可以使用 Flit Mode
Flit_Mode_EnabledInternal Variable协议/LTSSM 内部双方 Flit Mode 的最终协商结果
Flit Mode StatusStatusLink Status 2 Register软件可见的当前/即将采用的 Flit Mode 状态

最容易混淆的是 Flit Mode Supported 和 Flit_Mode_Enabled：前者回答“我有没有能力”，后者回答“这条 Link 本次训练最终用不用”。

2. TS 中的 Flit Mode Supported 从哪里来

TS1/TS2 中的 Flit Mode Supported 是本地能力与软件控制共同作用后的线上声明：

TS.FlitModeSupported = Capability.FlitModeSupported ∧ ¬ FlitModeDisable

因此，一个支持 Flit Mode 且没有被 Disable 的 Port，在初始训练第一次于 Polling.Active 发送 TS1 时，就已经可以把 Flit Mode Supported 置 1。

3. Polling：开始声明能力

Detect
  ↓
Polling.Active
  │
  │ TX TS1: Flit Mode Supported = 1
  │ RX TS1: Partner Flit Mode Supported

  └─ 双方开始知道对端是否支持 Flit Mode

这里必须注意：Polling 阶段获得的是对端的 capability advertisement，还不能把它等价成 Flit_Mode_Enabled=1。

4. Configuration.Linkwidth.Accept：形成协商结果

进入 Configuration 后，协议根据此前 Polling/Configuration 中交换的信息确定本次 Link 的 Data Stream Mode。关键结果由内部变量 Flit_Mode_Enabled 表示。

Configuration.Linkwidth.Start
             ↓
Configuration.Linkwidth.Accept
             │
             │  根据此前双方交换的
             │  Flit Mode Supported 信息
             ↓
       Flit_Mode_Enabled
          1 / 0
             │
             ├─ 1 → 本次 Link 使用 Flit Mode
             └─ 0 → 本次 Link 使用 Non-Flit Mode
一句话：Polling 是“我支持 Flit”；Configuration.Linkwidth.Accept 是形成“我们这条 Link 最终是否使用 Flit”的协商结果的关键阶段。

5. Configuration.Complete 与 64 GT/s Capability

到了 Configuration.Complete，Flit Mode 已经完成协商。对于初始 Link Training，满足规范规定的条件后，此时才允许使用特殊的 Supported Link Speeds = 1_0111b 来表示支持 2.5 GT/s through 64.0 GT/s inclusive。

Polling
  │  TS Flit Mode Supported
  ↓
双方交换 Flit capability
  ↓
Configuration.Linkwidth.Accept
  │
  └─ Flit_Mode_Enabled 确定
       ↓
Configuration.Complete
  │
  └─ Flit Mode has been negotiated
       ↓
满足条件时 Supported Link Speeds = 1_0111b
       ↓
声明 64 GT/s capability

1_0111b 表示的是 支持 64 GT/s，并不表示当前 TS 正在以 64 GT/s 传输。

6. Flit Mode 与 Gen6 速率是两个维度

64 GT/s ⇒ Flit Mode
Flit Mode ⇏ 64 GT/s

所以一个按 PCIe 6.x 协议设计、最高速率只有 32 GT/s 的 Component，仍然可以实现并成功协商 Flit Mode：

Max Data Rate = 32 GT/s
Flit Mode Supported = 1
        ↓
Polling: TS Flit Mode Supported = 1
        ↓
Configuration: Flit_Mode_Enabled = 1
        ↓
最终可以工作在：32 GT/s + Flit Mode

因此阅读 PCIe 6.x 新功能时，不能看到“PCIe 6.0 新增”就直接理解成“64 GT/s 专属”。应该继续判断该功能绑定的是 Data Rate 还是 Data Stream Mode。

7. L0s / L0p：一个典型例子

L0s/L0p 正好说明为什么必须区分 Flit Mode 和 Gen6 Data Rate。更准确的分类是：

Data Stream ModeL0sL0p
Non-Flit Mode可支持不使用
Flit Mode不支持可支持

因此“最高只有 Gen5/32 GT/s，但按 PCIe 6.x 实现”的设备，如果协商成 Flit Mode，并不能因为速率只有 32 GT/s 就简单套用 Non-Flit 的 L0s 规则。这里真正决定相关机制的是 Data Stream Mode。

9. 最终记忆模型

能力：Flit Mode Supported
软件控制：Flit Mode Disable
从哪里开始在线上声明：Polling.Active 的 TS1；随后 TS2 继续携带
协商结果：Flit_Mode_Enabled
关键协商阶段：Configuration.Linkwidth.Accept
到 Configuration.Complete：Flit Mode 已经 negotiated，满足条件时可以进一步声明 64 GT/s capability。

最重要的理解不是“Flit Mode 是 Gen6 的功能”，而是：Flit Mode 是一个独立的 Data Stream Mode；64 GT/s 强制要求它，所以很多 Flit Mode 规则表面上看起来像是 64 GT/s 规则。
